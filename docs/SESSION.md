# SESSION.md — start, resume and finish
## Practical use
### Resume without repeating work
Read the task record and current deliverable, then compare receipts with the latest relevant state. Classify each step as planned, attempted, applied or verified. Recover an uncertain operation before retrying it. At completion, leave enough evidence for another agent to establish the outcome without replaying the entire conversation.
## Portable task state
For substantial work, use STATUS.md — task state template as the continuity contract. The existing task record remains the primary home; a local status file can point to it and hold execution evidence. Do not create a second competing narrative merely to satisfy a filename convention. Resume from verified state, not an assumption that a platform remembered every prior action.
## Start or resume
Confirm objective, authorized changes, targets and destination. For an existing task, read the work record and deliverable before repeating extraction. Use saved manifests and receipts to establish what already happened.
## While working
Keep a task-specific scope, stable ID manifest, baseline, decisions, applied-operation journal and verification evidence. Re-read touched values before writes. A failed connection is not an empty dataset.
## Finish
Record outcome, evidence links, decisions, unresolved issues and next step in the appropriate work record. Report separately: draft; saved to Notion; submitted Geo proposal; executed edit; indexed verification; reconciled mirror.
Private context maintenance belongs to the agent’s private area. Shared task progress belongs to the assigned team record. A work record does not authorize new publication, messages or scheduling.
