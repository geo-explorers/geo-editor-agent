## Practical use
### Before updating a shared record
Resolve the current database schema and stable target identity. Read the fields you intend to change, preserve unrelated edits and use existing option values. Save the narrow update, read it back and link the affected record in the task result. Keep access failures distinct from empty query results.
Start at Agents flow center. Use Project tracking for projects, task records and documentation, Team communication for existing discussion and decision surfaces, and Geo content work for mirrors and reports.
Fetch current database schemas before writes. Resolve page and data-source IDs rather than relying on similar titles. Preserve authorship, proposals, intentional clears and reviewer-owned fields. A linked database view edits its underlying records.
