# Context locations — README section
## Practical use
### Resolve a context question
First identify whether the question concerns instructions, task progress, stored graph data or private working notes. Open the canonical record for that category, record its observation date and follow only the links needed for the task. If access fails, record the failure and use a dated fallback explicitly; do not interpret an inaccessible record as absent.
## Loading and ownership
This is a Geo team context map, read when locating the authoritative record or resolving ownership. Keep the map in the README’s Context locations section. It does not create memory or synchronize Notion and local files. See Agent purpose and responsibilities — instruction section and Folders and file placement — setup reference.
## Four homes
- Agent Composition: reusable shared documents, skills, workflow definitions and dependencies.
- Agent flows project and task trackers: assignments, deliverables, review and work status.
- Each agent’s private context: personal working memory and private journal.
- Local project: executable tools, scoped snapshots, baselines and receipts.
Geo holds current stored graph assertions. Notion holds editable team knowledge, proposals and work records. A local snapshot is dated evidence.
## Retrieve deliberately
Begin with the catalog and task record, follow the relevant document and skill links, and read their current versions. Do not assume every document is already loaded into context. Do not copy a private brain into a shared teamspace to solve navigation.
The team edition intentionally omits private page IDs, private journal content and account credentials.
