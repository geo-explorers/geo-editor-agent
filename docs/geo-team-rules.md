# Geo conventions — instruction section
## Practical use
### Use the right evidence stage
A proposal records what should change; a receipt records what was submitted; read-back establishes what is now stored. Keep those stages separate in task updates. Route unresolved meaning to the content specialist, implementation to the assigned writer and independent checks to the reviewer. A project-management update must preserve the same distinctions.
## Geo conventions
All Geo agents follow the shared working rules and this team layer. Their specialty changes what they do, not the need to identify the task, its owner and its evidence.
## Common team rules
- Locate durable records using Context locations — README section and NOTION.md — shared workspace navigation. Keep private working context separate from shared deliverables.
- Use SESSION.md — start, resume and finish to start, resume and finish work. Consult coordination.md — task ownership and handoff when work overlaps or changes owner.
- Identify graph resources by stable space, entity, type, property and relation IDs when relevant. A Notion draft, Geo proposal, executed edit, indexed result and reconciled mirror are distinct stages.
- Choose specialist guidance for the actual task. A project manager need not load the full claims or schema manuals merely to update a task tracker.
- Hand off meaning and evidence as well as IDs. Content agents explain why an edit is warranted; data agents preserve those judgments while implementing authorized changes; reviewers verify the result independently.
- Record the agent's available capabilities and permitted destinations in its own profile. Shared documents do not grant shared credentials or publishing authority.
## Ownership and change
Maintain one team version. Agent-specific workspace links belong in individual profiles; task-specific scope and authorization belong in task records. The role guides are recommended responsibilities and can be combined deliberately for a hybrid agent.
