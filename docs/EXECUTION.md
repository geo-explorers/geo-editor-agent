# EXECUTION.md — changes and verification
## Practical use
### Change record
Before writing, record the exact destination, intended values, relevant current values and applicable authorization. After writing, attach the receipt and read back the affected values and links. If the outcome is uncertain, inspect transaction state and identities before retrying. Report the verified outcome and any remaining gap separately.
## Define the change
Record requested fields, destination, before-values, intended after-values and ownership. Separate mirrored data, editorial proposals, review decisions and reviewer markers. Preserve unrelated content.
## Check before writing
Resolve schema and identities, inspect semantic duplicates, validate data types and Types relations, and compute the exact diff. Compare baseline, current Notion and current Geo for a return path. Recheck touched values immediately before publication.
## Execute and recover
Use the relevant skill safeguards and applicable user authorization. Keep one coordinated writer for overlapping targets. Record every applied operation. Resolve uncertain creates and submissions from identity lookup and receipts before retrying.
## Verify
Check the stored values and relations, then check that their meaning meets the task. Read affected neighbors when links or hierarchy change. A successful transaction is not proof that the indexed graph or mirror is correct.
