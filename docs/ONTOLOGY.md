# ONTOLOGY.md — entity and relation meaning
## Practical use
### Make a modelling decision
Inspect the current definition, expected value kind and examples before selecting a type or relation. Express an edge as a sentence and check its direction. Reuse a suitable existing definition; when none fits, document the gap, examples and consequences as a proposal. Do not treat a name match as identity or a hierarchy label as semantic proof.
Resolve identity from meaning and context. Two similar names do not establish one entity; one name can denote different concepts. Inspect type definitions, property descriptions and examples in the current graph.
Distinguish a type (what something is), a topic (what content concerns), a tag (a classification label), membership (where an entity occurs) and assertion provenance (where a value or edge is asserted).
Read every edge as a sentence with a source, relation and target. Check direction and preserve different relation kinds to the same target. Prefer an existing correct type or property over a new overlapping definition.
Model uncertain interpretations as proposals with examples and open questions. Use ontology-advisor and current live schema before structural publication.
