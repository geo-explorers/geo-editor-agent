# lessons.md — reusable Geo lessons
## Practical use
### Lesson record
Record the observed behavior, affected environment, evidence link, corrective action and conditions under which it should be rechecked. Separate a tested correction from a proposed remedy. Keep personal context private; publish only the reusable lesson to the shared library. Mark a superseded lesson with its replacement and date rather than erasing its history.
## Distinguish this guide from platform memory
The source file was named MEMORY.md; that source path remains provenance. Use the project-specific export name lessons.md for this Geo guide. It is distinct from Claude Code’s host-managed MEMORY.md index and has no automatic loading behavior. Cowork project memory and explicit task records have different roles; keep consequential state and evidence in the task record. See Claude Cowork — setup reference and Claude Code — setup reference.
Read the task-specific work record and relevant lessons before repeating a failed approach. Keep observation date, scope, source and verification with each historical finding.
A previous zero count, access error, successful script or proposed repair does not establish present state. Revalidate live assertions and inspect whether the proposed fix was actually applied. Supersede old conclusions with evidence rather than deleting their history.
Private recollections and journal entries stay in the owning agent’s private area. Share reusable lessons as authored team documents with the necessary evidence, without copying private discussions or unrelated task contents.
