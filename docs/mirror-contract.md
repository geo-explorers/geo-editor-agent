# mirror-contract.md — Geo to Notion
## Practical use
### Mirror acceptance criteria
Every selected source entity has one traceable destination row; each supported value and relation retains its source identity and scope. Refresh preserves pending proposals and review fields. Record unsupported data explicitly. Use the current readiness source to distinguish implemented text publication from remaining relation, creation and clearing work; do not label the entire return path complete or absent.
Record source space, selection, date meaning, endpoint and fetch time. Preserve Geo IDs and assertion spaces for every mapped field and edge. Enumerate all scoped entities and required nested relations.
Create or resolve rows before linking them. Preserve relation type, edge identity, relation-entity identity and position. Distinguish same-space values from deliberate sibling-space fallbacks. Retain raw names and transport encoding without silently changing content.
Separate Geo-backed columns from proposed wording, review state and QA markers. Compare the saved baseline, current Notion and current Geo before refreshing; preserve unsynced edits and surface conflicts.
Verify row counts, identity uniqueness, values and relation endpoints. A fresh mirror with no edits must produce zero proposed return-path changes. Consult the linked readiness report: the generic round trip remains incomplete.
