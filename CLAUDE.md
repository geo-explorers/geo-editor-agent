# Claude Code specifics

Everything above is shared across hosts. This section is only what Claude Code does differently.

## Skills load automatically — through stubs

`.claude/skills/<name>/SKILL.md` exists for every toolkit skill so Claude Code discovers it
at startup and can trigger on its description. **Each is a stub.** Its body tells you to
read the real contract at `skills/<tier>/<name>/SKILL.md` and follow that. Do so before
running any part of a skill — the hard rules, gates and script paths are only there.

Three general-purpose skills are vendored in full, not stubbed: `notion-knowledge-capture`,
`notion-research-documentation`, `karpathy-guidelines`. Each carries a `PROVENANCE.md`.

Stubs are generated by `tools/gen-skill-stubs.mjs`. Never edit one by hand.

## Subagents

`.claude/agents/` holds four definitions. Invoke by name or by describing the job:

| Agent | Use it for |
|---|---|
| `geo-agent` | any Geo or Geo↔Notion task planned end to end, up to the dry-run |
| `geo-task` | a reviewable plan for a Geo-work task, read-only, before anyone executes |
| `geo-mirror-refresh` | refreshing the "- new" Notion mirrors, or mirroring a space into a page |
| `geo-research` | a cited research draft under the trusted-sources allowlist |

A subagent has **no Notion connector** — only the integration token via
`scripts/notion-read.mjs`. Never hand one a plan that assumes connector access. None of
them can publish; the editor does that in this session.

## Running things

- Always from the repository root. `.env`, `src/` and `skills/` resolve from there.
- Load env only through Node's flag: `node --env-file=.env …`. There is no `dotenv` wiring
  in the skill scripts, and a token must never be passed on the command line.
- Node **22+**. Its type-stripping runs the `.ts` skill scripts directly; `bun` is not used.
- `.claude/settings.json` pre-approves the skill and tool scripts. Anything outside those
  patterns will prompt — that is deliberate.
- Long writes (a 250-row mirror is ~9 minutes) run in the background with progress
  polling, never in a silent foreground stretch.

## Verify before you trust

`node tools/doctor.mjs` checks the runtime, the env variable names, the stubs, the skill
integrity manifest and reachability of Geo and Notion. Run it when something looks off,
and after any `tools/sync-upstream.mjs`.
